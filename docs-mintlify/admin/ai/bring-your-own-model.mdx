Bring Your Own Model (BYOM) lets you connect your own LLM provider to power
AI agents in Cube, instead of using the built-in models. This gives you full
control over which models your agents use, where your data is processed, and
how you manage AI costs.

## Supported providers

| Provider | Chat models | Embedding models |
| --- | --- | --- |
| **Anthropic** | Yes | No |
| **OpenAI** | Yes | Yes |
| **AWS Bedrock** | Yes | Yes |
| **GCP Vertex AI** | Yes | No |
| **Databricks** | Yes | No |
| **Snowflake Cortex** | Yes | No |
| **Custom OpenAI-compatible** | Yes | No |
| **Custom Anthropic-compatible** | Yes | No |

## Configuration

### Step 1: Add a model

Before assigning a BYOM model to an agent, you need to register it in the
admin panel:

1. Navigate to **Admin > Models**
2. Click **Add model**
3. Provide a **name** for the model
4. Select the **model type**: LLM, [Small LLM](#small-llm) or Embedding model
5. Choose a **provider** and **model**. Custom OpenAI-compatible and Custom
   Anthropic-compatible have no model list: you enter the model name with the
   endpoint settings instead
6. Enter the required credentials for the provider

### Step 2: Assign the model to an agent

Once a model is registered, reference it in the agents YAML configuration by
name or ID:

```yaml
agents:
  - name: sales-analyst
    llm:
      byom:
        name: "my-anthropic-model"
    small_llm:
      byom:
        name: "my-anthropic-haiku"
    embedding_llm:
      byom:
        name: "my-bedrock-embeddings"
```

Each agent can use a different model. If no BYOM model is specified, the agent
uses the built-in default.

<Warning>

Switching embedding models for an agent means existing memories stored with
the previous embedding model will not be compatible. Memories are tied to the
embedding model that created them.

</Warning>

## Small LLM

The agent runs short tasks, such as chat titles, suggested questions and
memory, on a small LLM. A small LLM is a model of type **Small LLM**, so it can
come from a different provider or account than the agent's LLM. For example,
an agent can answer questions with GLM through a Custom OpenAI-compatible
model and run short tasks on Claude Haiku 5.5 through Anthropic.

### Adding a small LLM

Add a small LLM the same way as any other model: in **Admin > Models**, click
**Add model**, select the **Small LLM** model type, and choose a provider,
model and credentials.

### Assigning a small LLM to an agent

Pick the agent's small LLM in the **Small LLM** field of the agent's settings,
or with the `small_llm` property in the agents YAML configuration. It accepts
`auto`, a built-in model (`claude-haiku-5-5` or `gpt-6-luna`), or a BYOM
reference to a model of type **Small LLM**:

```yaml
agents:
  - name: sales-analyst
    llm:
      byom:
        name: "glm-gateway"
    small_llm:
      byom:
        name: "anthropic-haiku"
```

Built-in small LLM ids use hyphens, unlike the [`llm`](/admin/ai#llm) names:
write `claude-haiku-5-5`, not `claude_5_5_haiku`.

With `auto`, the default, an agent on a built-in LLM uses a built-in small
LLM. An agent on a BYOM LLM uses a small LLM from the same provider, region
and credentials as its LLM:

| Provider | Small LLM with `auto` |
| --- | --- |
| **Anthropic**, **AWS Bedrock**, **GCP Vertex AI** | Claude Haiku 5.5 |
| **OpenAI** | `gpt-6-luna` |
| Other providers | The LLM itself |

<Tip>

If the agent's LLM is a BYOM model, keep its small LLM on BYOM too. A built-in
small LLM consumes Cube AI tokens (see [Billing](#billing)).

</Tip>

If the provider refuses a BYOM small LLM (for example, the model is not enabled
for your account or region), the agent falls back to `auto`. If the provider
refuses the `auto` small LLM of a BYOM LLM too, the agent runs these tasks on
the LLM itself.

On AWS Bedrock with `auto`, the small LLM is called on demand in the LLM's
region; the LLM's inference profile does not apply to it. A Bedrock model of
type **Small LLM** uses its own region and inference profile.

## Network configuration

If your provider requires IP allowlisting, allowlist the Cube
[egress IP addresses](/admin/deployment/infrastructure#egress-ip-addresses).
Agents that run in the control plane call your provider from the control-plane
addresses; agents that run in a single-tenant or BYOC region call it from that
region's own egress IPs.

## Billing

When using a BYOM model, **Cube AI tokens are not consumed**. You are billed
directly by your model provider based on their pricing. The exception is an
agent with a built-in [small LLM](#small-llm): its short tasks consume Cube AI
tokens.

This means:

- No Cube token quota is deducted for BYOM chat requests
- Administrators can see BYOM requests with their token counts, at no cost,
  in the **AI Tokens Usage** tab, and they're recorded in the
  **AI Calls & Cost** view in [Usage Analytics][ref-usage-analytics]
- Per-seat token grants and token packages do not apply

See [AI Tokens][ref-ai-tokens] for details on how token billing works with
built-in models.

## Provider-specific notes

### Extended thinking

Anthropic, AWS Bedrock, and GCP Vertex AI support extended thinking for
Claude Sonnet 3.7 and all later Claude models, and so does
[Custom Anthropic-compatible](#custom-anthropic-compatible). Turn it on or off
with the **Enable thinking** toggle in the model settings. The toggle is on by
default when you add a model. With thinking on, the agent's reasoning shows in
the chat. For the Chat API, see its [`thinking` field][ref-chat-api-thinking].

### Anthropic

Requires an API key.

### AWS Bedrock

- Credentials are optional — if left empty, the default AWS credential chain
  is used (e.g., workload identity)
- Supports assume-role configuration for cross-account access
- Supports inference profiles

### GCP Vertex AI

Requires a service account JSON key for authentication.

### Databricks

Requires a workspace URL and access token.

### Snowflake Cortex

Supports two authentication methods:

- JWT authentication
- Key-pair authentication (requires an encrypted PKCS#8 PEM private key)

### Custom OpenAI-compatible

Points an agent at any endpoint that implements the OpenAI chat completions
API — for example, an internal LLM gateway.

- **Model** and **base URL** are free text; the base URL must use `http` or
  `https` and may not target a loopback or link-local host
- The base URL is the API root, including the version segment: requests go
  to `<base URL>/chat/completions`, so use e.g. `https://gateway.acme.com/v1`
- A [small LLM](#small-llm) on this provider takes any model id, so it can
  use a smaller model behind the same endpoint
- **API key** is optional — leave it blank if your endpoint authenticates
  requests some other way, such as a custom header
- You can add custom HTTP headers sent with every request. Header values may
  include placeholders resolved per request from the caller's identity:
  `{{userId}}`, `{{userExternalId}}`, `{{email}}`, `{{username}}`,
  `{{tenantId}}`, `{{tenantName}}`, `{{tenantUrl}}`, `{{deploymentId}}`, and
  `{{agentId}}`. A placeholder with no value for a request — `{{userExternalId}}`
  for a user who did not arrive through signed embedding, for example — is sent
  through as literal text

### Custom Anthropic-compatible

Points an agent at any endpoint that implements the Anthropic messages API.
Configuration is the same as [Custom OpenAI-compatible](#custom-openai-compatible):
a free-text model and base URL, an optional API key, and optional custom
headers with the same placeholders.

Unlike the OpenAI-compatible provider, requests go to `<base URL>/v1/messages`,
so leave out the version segment — use `https://gateway.acme.com`, not
`https://gateway.acme.com/v1`. The API key, when set, is sent in the
`x-api-key` header.

[Extended thinking](#extended-thinking) is available for this provider. Since
the model name is free text, also pick the **Thinking mode** that matches the
model behind your endpoint:

- **Adaptive** — Claude Opus 4.7 and later, Sonnet 5 and later, Haiku 5.5 and
  later, and Fable 5 and later. This is the default
- **Budgeted** — Claude Sonnet 3.7 through 4.6, Opus 4 through 4.6, and Haiku 4.5

A mode that doesn't match the model makes every request fail: adaptive models
reject a thinking budget, and older models don't support adaptive thinking.
If the model doesn't support extended thinking at all, turn **Enable thinking**
off. Small-model tasks run without thinking.

## Troubleshooting

### Rate limit errors

If you see rate limit errors, the limits are enforced by your model provider,
not by Cube. Check your provider's rate limits and usage quotas.

### Authentication errors

Verify that the API key or credentials configured for the model are valid and
have the necessary permissions.

### Model not found

Ensure the model ID configured in Cube matches a valid model offered by your
provider. Model availability may vary by region.
