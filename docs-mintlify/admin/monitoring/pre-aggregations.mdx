The Pre-Aggregations page in Cube Cloud allows you to inspect all
[pre-aggregations][ref-caching-gs-preaggs] in your deployment at a glance. You
can see which pre-aggregations are accelerating queries, if they are [being
refreshed][ref-caching-using-preaggs-refresh], along with the last 24 hours of
build history.

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/pre-aggregations-list.png"
    alt="Pre-Aggregations page listing pre-aggregations with their last build time, duration, partition size and partitions"
  />
</Frame>

The built-in Admin and Developer roles can open this page and build
pre-aggregations; the Explorer and Viewer roles can't open it. To let other users
check pre-aggregation status without building, give them a [custom
role][ref-custom-roles-deployment-permissions] (Enterprise plan) with
**Access deployment** and **View pre-aggregations**. They see the page
read-only: **Build all**, **Build N selected**, and the controls that cancel
queued or running builds are hidden.

## Exploring pre-aggregations

You can switch between [pre-aggregations](#pre-aggregations) and
[build history](#build-history) by switching between the 
​**Pre-Aggregations** and **Build history** tabs.

## Pre-aggregations

The **Pre-Aggregations** tab shows a list of all configured
[pre-aggregations][ref-caching-gs-preaggs] for the deployment, and is useful for
quickly checking details such as when the last build occurred, how long the
build took to complete, the total size of the pre-aggregated data, and how many
partitions the data is split across. To see more information about a specific
pre-aggregation, click on it.

### Partitions

The **Partitions** tab shows all partitions (as specified by
[`partitionGranularity`][ref-model-ref-preaggs-partition-granularity]) of the
pre-aggregation. In the example below, the pre-aggregation has a single
partition:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/partitions-single.png"
    alt="Partitions tab of a pre-aggregation with a single partition and the Build all button"
  />
</Frame>

Pre-aggregations with multiple partitions show a list of all partitions, which
is helpful for checking pre-aggregation partition build times and sizes:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/partitions-multiple.png"
    alt="Partitions tab of a pre-aggregation partitioned by year, with each partition build time and size"
  />
</Frame>

Ideally partitions should be of a similar size and build time. If a partition is
taking significantly longer to build than others, it may be worth investigating
why.

If the pre-aggregation requires rebuilding (usually due to the underlying data
changing in a significant way), clicking **Build all** rebuilds **all**
partitions of the pre-aggregation.

You can also choose to rebuild **specific** partitions by selecting them and
then clicking the **Build N selected** button:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/build-selected.png"
    alt="Partitions tab with three partitions selected and the Build 3 selected button"
  />
</Frame>

Builds started from a staging or development environment land in the same
pre-aggregations schema as production. Production never serves tables built
for a pre-aggregation that the branch changed, but the build can remove older
unused production tables. See
[Deployment environments → Pre-aggregations][ref-environments-preaggs] before
building large pre-aggregations from a branch.

### Definition

The **Definition** tab shows how the [pre-aggregation is defined in the
data model][ref-model-ref-preaggs] without having to switch to the **Data
Model** page:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/definition.png"
    alt="Definition tab of a pre-aggregation showing its definition as JSON"
  />
</Frame>

### Preview

To see a sample of the data contained in the pre-aggregation, click the 
​**Preview** tab:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/preview.png"
    alt="Preview tab of a pre-aggregation showing sample rows of pre-aggregated data"
  />
</Frame>

This can be used to verify that the data within the pre-aggregation is being
built correctly.

### Used By

The **Used by** tab shows recent queries that used this pre-aggregation
for acceleration:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/used-by.png"
    alt="Used by tab of a pre-aggregation listing recent queries that it accelerated"
  />
</Frame>

This is especially useful for checking that the pre-aggregation is being used as
expected by queries sent to the deployment.

### Indexes

[Indexes][ref-model-ref-preaggs-index] significantly improve the performance of
configured pre-aggregations. The **Indexes** tab displays any configured
indexes for this pre-aggregation:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/indexes.png"
    alt="Indexes tab of a pre-aggregation listing an index and its columns"
  />
</Frame>

## Build History

The **Build history** tab shows the last 24 hours of build history for
all pre-aggregations in the deployment. From here, you can see if a
pre-aggregation build succeeded (or failed), how the build was triggered, when
the build started, and how long it took to complete.

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/build-history.png"
    alt="Build History tab listing pre-aggregation partition builds with their status, trigger, start time, duration and size"
  />
</Frame>

To see more information about a specific build, click on it:

<Frame>
  <img
    src="https://static.cube.dev/docs/admin/monitoring/pre-aggregations/build-details.png"
    alt="Build details page with the build status, trigger, table name, partition size and build steps"
  />
</Frame>
