---
title: Charts
description: Display reports from your workbook as visualizations on the dashboard.
---

Chart widgets display a report from the source [workbook][ref-workbooks] as a visualization on the dashboard. Every chart on a dashboard is backed by a tab in the workbook — when you publish a new version of the workbook, the chart updates accordingly.

## Adding a chart

In the [dashboard builder][ref-workbooks], open the **Charts** picker, the first item in the toolbar, and select one or more reports from the workbook. A chart is added to the canvas for each selected report, inheriting the report's query, configured visualization, and styling. The picker lists every workbook tab that has a query, the ones already on the dashboard first. It has a search field once the workbook has five or more such tabs; with fewer, it lists them without one. A name too long for the list shows in full when you hover it; on a phone it wraps instead.

### Creating a chart from the builder

The first row of the **Charts** picker, directly below the search field when the picker has one, is **Create in workbook**. It stays there whatever you type in the search, and it is the picker's only row when the workbook has no tab with a query yet, or when no chart matches the search.

Click **Create in workbook** to switch to the workbook on a new tab, added at the end of its tabs and opened on the [new tab page][ref-new-tab-page]. It is named like any new tab, **Tab** and a number such as **Tab 3**, until its first query [names it][ref-tab-names]. Build the chart's query there, then return to the builder (click the **Builder** tab, or press the browser's back button) and pick the tab in the **Charts** picker to add it. Creating the tab doesn't change the charts on the dashboard.

From the keyboard, press <kbd>Enter</kbd> on the **Charts** picker to open it: **Create in workbook** is already highlighted, so a second <kbd>Enter</kbd> creates the tab, and <kbd>↓</kbd> moves to the charts. The charts already on the dashboard stay on it.

The tab is created the same way as one you add in the workbook itself, so one **Undo** in the workbook removes it again. After that undo, the browser's back button still returns to the builder.

## Interaction with controls

Charts respect the [controls][ref-controls] placed on the same dashboard — filters, time granularity switchers and field switchers. A single control can drive multiple charts at once: its value is applied to every chart built on the same semantic view as the control's member. For charts on other views, map the control from the chart's [Controls mapping][ref-controls-mapping].

If some controls are incompatible with a chart's query, the chart skips them and shows a warning icon. See [Incompatible controls][ref-incompatible-controls] for details.

## Updating charts

Charts on a published dashboard reflect the most recent published version of the workbook. To change the query, switch the chart type, or restyle the visualization, edit the underlying report in the workbook and publish a new version of the dashboard.

The chart's settings menu (`⋮`) groups its items by what they do: **Inspect** and **Ask a follow up question**, then **Comment on this chart** and **Create alert**, then **Edit in workbook**.

**Inspect** in the chart's settings menu shows the chart's query — see [Inspecting a chart's query](#inspecting-a-charts-query).

**Ask a follow up question** in the chart's settings menu starts a [chat][ref-chart-follow-up] about this chart.

**Comment on this chart** in the chart's settings menu opens the [comments][ref-comments] panel with only this chart's threads.

**Create alert** in the chart's settings menu opens a new [alert][ref-data-alerts] with this chart already picked, or an upgrade dialog on a plan without dashboard deliveries. In the builder it is enabled only once the chart is in the published dashboard — see [From a chart's menu][ref-data-alerts-menu].

**Edit in workbook** in the chart's settings menu opens that report directly, on its own workbook tab.

### Filters carried into the workbook

The dashboard's [filters][ref-controls] come along, so the report opens showing the same slice of data the chart was showing rather than re-running over everything.

They sit in the report's filter bar next to its own filters, tinted violet to set them apart, and read the same way — member, operator, value. Hovering one says **From dashboard**. What is different is that they are not the report's:

- they apply to the results on screen, and are **not** saved to the report. Publishing the workbook again will not pin them onto the chart for everyone.
- their values cannot be changed in the workbook. To explore a different value, add your own filter on the same field, or change the dashboard's control and reopen the chart.
- they can be dropped, but not kept: **Clear filter** on the chip removes it for the rest of the session and the report re-runs without it. Reopening the chart from the dashboard brings the current values back.

To change what a viewer of the dashboard can filter by, edit the [filter control][ref-controls] there — not the report.

When the report already filters the same field, both filters apply — exactly as they do on the dashboard, so the numbers match the chart you came from. A carried filter that says precisely what the report already says is left out rather than shown twice.

Only filters are carried. A [time granularity switcher or field switcher][ref-controls] on the dashboard does not follow into the workbook, so a report opened this way shows its own granularity and its own fields.

## Inspecting a chart's query

On a published dashboard, **Inspect** in a chart's settings menu (`⋮`) opens a dialog with the query behind the chart. The query has the dashboard's current state applied: the values of its [controls][ref-controls] and any [cross-filters][ref-cross-filtering]. It is the query that produced the data on screen, so change a filter and reopen the dialog to see the query change with it.

The dialog's title is the chart's title. When filters reach the chart, a line under the title lists them, worded as on the dashboard's filter chips, such as **Status is completed**. Cross-filters come last, as **Filtered by** and the names of the cross-filtered fields.

The query is shown on the **Semantic SQL** and **Generated SQL** tabs, as in a workbook's [SQL panel][ref-inspecting-queries], with a button to copy it:

- **Semantic SQL** is shown to everyone who can view the dashboard.
- **Generated SQL** is shown only to roles with the [**Access SQL Runner**][ref-custom-roles-actions] permission. Without it, the dialog shows only Semantic SQL.

A chart built on [source SQL][ref-source-sql] shows its SQL as written, without tabs, and only to roles with **Access SQL Runner**. For other viewers, such a chart has no **Inspect**. Dashboard filters do not apply to source SQL, so the dialog lists none.

If a chart's query fails, **Inspect** also appears as an icon button next to the error, so you can read the query that failed.

A viewer whose role allows no other item in the settings menu, for example one who can't use the [Dashboard Agent][ref-dashboard-agent], still gets the menu with **Inspect** in it.

**Inspect** is not available on Python charts, on [embedded][ref-embedding] dashboards, in printed or PDF dashboards, or in a dashboard's version history.

## Title

Each chart shows the name of the underlying workbook tab as its title. To rename it, open the tab in the workbook, rename the tab, and republish the dashboard — the new name flows through to every chart backed by that tab.

Use **Hide title** in the widget's settings menu to suppress the title on the dashboard — useful when the chart's content already makes the subject obvious, or when an adjacent [text widget][ref-text] provides its own heading. Choose **Show title** in the same menu to bring it back.
