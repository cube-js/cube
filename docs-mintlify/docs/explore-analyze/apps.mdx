<Warning>

Apps are currently in preview, and their capabilities and authoring experience may
still change. Reach out to the [Cube support team](/admin/account-billing/support)
to activate this feature for your account.

</Warning>

Apps let you go beyond a dashboard's grid of widgets. An app is a custom,
interactive interface with its own layout, components, and controls, powered by
live data from reports in a Cube workbook.

Use an app when you need a guided workflow, a custom visual presentation, or an
interactive data tool that does not fit a standard [dashboard][ref-dashboards]
layout. A workbook holds one dashboard, and that dashboard is either a standard
dashboard or an app.

## Turn a dashboard into an app

Open a workbook and switch to **Dashboard builder**. In the workbook menu, select
**App mode**. Cube replaces the dashboard with a starter app that you can edit,
and the **Dashboard builder** tab reads **App builder**.

To go back to a standard dashboard, select **App mode** again. The tab reads
**Dashboard builder** again. Cube keeps the standard dashboard's draft while the
workbook is in app mode, so switching back restores it.

## Build the app with the agent

Describe the app you want in the agent chat. Include the business question, the
data you want to show, and how people should interact with it. For example:

> Build a revenue performance app with headline metrics, a monthly trend chart,
> and a searchable status filter. Use the company's brand colors.

The agent creates the workbook reports, writes the app's files, and adds reusable
components for common elements such as KPI cards, tables, line, bar, and area
charts, tabs, and searchable controls. It then runs the app and fixes the errors
that it finds. Continue prompting the agent to adjust the layout, behavior, or
styling.

## Preview and edit the code

The app editor has two modes:

- **Preview** shows the running app. Use it as your viewers will.
- **Code** shows the app's **Files** and a code editor. Select a file to edit it.

An app is made of JavaScript, CSS, and JSON files. The app starts from its entry
file, which **Files** marks as **Entry**. Components are copied into the app's
files, so you can change their code and styling for this app.

Your code edits are not saved as you type. The editor shows how many files have
unsaved changes:

- Click **Run** to save all changed files and reload the app with them.
- Click **Discard** to drop your unsaved changes.

<Note>

If you leave the workbook before you click **Run**, your unsaved changes are lost.

</Note>

## Publish the app

Click **Publish** to publish the app, the same way you
[publish a dashboard][ref-publishing]. Cube refuses to publish an app that has no
entry file or whose entry file is empty.

Viewers see the published app read-only. It uses the report definitions from
the version you published, and Cube runs these reports for each viewer. Viewers
cannot open the app's code. The app follows the viewer's light or dark theme and
locale.

## Governed data access

An app reads only the results of reports in its own workbook. Cube runs those
reports with the viewer's permissions and passes the results to the app. The app
does not receive credentials for your data source or Cube APIs, and it cannot
query your warehouse directly.

Apps run in a sandbox, isolated from the Cube interface:

- An app cannot make network requests, so it cannot call external APIs or send
  data out of Cube.
- An app cannot load external scripts, stylesheets, images, or fonts. Put
  everything the app needs in its files. Images and fonts can be embedded as
  `data:` URLs.
- An app cannot read Cube cookies, storage, or the page around it.

## When an app fails

- **This app hit an error** — the app's code threw an error while it
  ran. The message shows the error. Fix the code, or ask the agent to fix it,
  and click **Run**.
- **Couldn't load the app's source** — Cube could not fetch the app's files, so
  the editor did not open. Click **Reload** to try again.

## Preview limitations

During preview:

- Apps cannot be shown in [embedded analytics][ref-embedding].
- Workbooks with an app cannot be promoted to another deployment.
- Scheduled refreshes and deliveries are not supported for apps.
- Dashboard [filters and controls][ref-controls] do not apply to an app. Build the
  controls into the app instead.
- An app cannot read reports from [Source SQL tabs][ref-source-sql-tabs].
- Apps can read workbook report results but cannot write data back to a source.
- Available components and APIs may change as the feature develops.
