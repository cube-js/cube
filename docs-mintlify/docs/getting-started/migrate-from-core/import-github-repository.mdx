---
title: Import a GitHub repository
description: "This guide walks you through setting up Cube Cloud, importing a GitHub repository with an existing Cube project, and connecting to your database."
---

## Step 1: Create an account

Navigate to [cubecloud.dev](https://cubecloud.dev/), and create a new Cube Cloud
account.

## Step 2: Create a new Deployment

Click **Create deployment**. This is the first step in the deployment
creation. Give it a name and select the cloud provider and region of your
choice.

<Frame>
  <img src="https://static.cube.dev/docs/shared/deployment-wizard/create-deployment-v2.png" alt="Create deployment step of the deployment wizard with the name, cloud platform and region" />
</Frame>

<Info>

Microsoft Azure is available on [Enterprise plan](https://cube.dev/pricing).
[Contact us](https://cube.dev/contact) for details.

</Info>

## Step 3: Import repository from GitHub

Click **Import from a GitHub repository** and complete any requested GitHub
authorization. After authorization, you should see this screen:

<Frame>
  <img src="https://static.cube.dev/docs/shared/deployment-wizard/github-repository-v2.png" alt="Select a GitHub organization and repository step with the organization, repository, default branch and project directory fields" />
</Frame>

Select the **account that owns the repository** (your personal account or
organization). If it is missing, choose **Add organization** in the account
selector to open GitHub's app installation dialog. Install the Cube Cloud GitHub
app on that account and grant it access to the repository. Complete any required
organization-owner approval before selecting the repository. See
[GitHub App permissions][ref-continuous-deployment] for access requirements and
[creating a repository][ref-create-repository] for the new-repository flow.

Select your repository and the desired branch to use as the default. If the
repository is a monorepo, you should also provide the path to the Cube project
within it. Deployments connected to a Git monorepo will trigger a rebuild
**only** when committed files begin with the provided path.

## Step 4: Connect your Database

Enter your credentials to connect to your database. Check the [connecting to
databases][link-connecting-to-databases] guide for more details.

<Info>

Want to use a sample database instead? We also have a sample database where you
can try out Cube Cloud:

<br />

| Field    | Value              |
| -------- | ------------------ |
| Host     | `demo-db.cube.dev` |
| Port     | `5432`             |
| Database | `ecom`             |
| Username | `cube`             |
| Password | `12345`            |

</Info>

<Frame>
  <img src="https://static.cube.dev/docs/shared/deployment-wizard/database-picker-v2.png" alt="Set up a database connection step with the grid of data sources" />
</Frame>

In the UI it'll look exactly like the image below.

<Frame>
  <img src="https://static.cube.dev/docs/shared/deployment-wizard/postgres-connection-v2.png" alt="PostgreSQL connection form filled in with the sample database credentials" />
</Frame>

If you run into issues here, make sure to allow the Cube Cloud IPs to access
your database. This means you need to enable these IPs in your firewall. If you
are using AWS, this would mean adding a security group with allowed IPs.

## Step 5: Check the deployment

Cube builds the data model from your repository and spins up your
deployment. The **Status** page shows the build, the deployment's resources,
and the activity log:

<Frame>
  <img src="https://static.cube.dev/docs/shared/deployment-wizard/status-page-v2.png" alt="Status page of a new deployment with its integrations, resources and activity log" />
</Frame>

You're ready for the last step, running queries in the Playground.

## Step 6: Try out Cube Cloud

Now you can navigate to Playground to try out your queries or connect your
application to Cube Cloud API.
