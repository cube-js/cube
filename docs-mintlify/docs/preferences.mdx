Each user can customize their Cube experience from the **Preferences** page
(`/preferences`), accessible from the user menu. These settings are saved to your own
account, apply across all devices, and don't affect other users in the account.

| Preference | Description | Default |
| --- | --- | --- |
| Theme | Choose between System, Light, or Dark visual theme | System |
| Language | Choose the language for the Cube interface | English (US) |
| Time zone | Run your queries in this time zone, so dates like "today" match your local day | Deployment default |
| Sidebar drawer | Show only icons and expand the sidebar on hover | Off |
| Pointer cursors | Use pointer cursors on interactive elements | On |
| Code editor | Switch to the new CodeMirror-based code editor for data models | Off |
| New message scrolling | Automatically scroll to new messages in chat | On |
| Alternating row colors | Highlight alternating rows in data tables | Off |
| Default deployment | Open this deployment when you go to Cube without one in the URL | Account default |
| Notifications | Choose whether alert, budget, comment, sharing, access-request, dashboard review and dbt sync notifications also arrive by email | On |

## Language

The Cube interface is available in 10 languages across 12 locales (Spanish and
Portuguese each have two regional variants). Set your language from the
**Language** picker in the **Appearance** section of the **Preferences** page. The
setting is per-user — it's stored on your profile and follows you across browsers and
devices. It also determines the language of transactional emails you receive from Cube,
such as budget alerts.

| Language                   | Locale code |
| -------------------------- | ----------- |
| English (US)               | `en-US`     |
| Deutsch (Deutschland)      | `de-DE`     |
| Español (España)           | `es-ES`     |
| Español (Latinoamérica)    | `es-MX`     |
| Français (France)          | `fr-FR`     |
| Italiano (Italia)          | `it-IT`     |
| 日本語 (日本)               | `ja-JP`     |
| Norsk bokmål (Norge)       | `nb-NO`     |
| Português (Brasil)         | `pt-BR`     |
| Português (Portugal)       | `pt-PT`     |
| Svenska (Sverige)          | `sv-SE`     |
| Tiếng Việt (Việt Nam)      | `vi-VN`     |

English (`en-US`) is the default and the fallback when no language is configured.

<Info>

To set the language of **embedded** Cube surfaces (dashboards, Analytics Chat, and
Creator Mode) instead, see [embedding localization](/embedding/iframe/localization).

</Info>

## Time zone

By default your queries run in the deployment's
[default time zone](/docs/data-modeling/configuration#default-time-zone). If your admin has
enabled **user time zones** and left personal time zones allowed, you can pick your own
under **Time zone** on the **Preferences** page — so time dimensions bucket into your
local day and `today` means your today.

Only a zone you pick is applied; Cube never silently switches you to your browser's zone.
If your device is somewhere else, Cube offers the detected zone as a dismissible
suggestion rather than applying it.

Leaving it as **Deployment default** follows the account-wide zone your admin set, or the
deployment's default time zone when there isn't one. The control is hidden when your admin
has not enabled the feature, or has turned off personal time zones — in that case
everyone queries in the account-wide zone.

See [Time zones](/admin/time-zones) for what a zone changes and how dashboards carry their
own.

## Default deployment

On an account with more than one deployment, **Default deployment** on the **Preferences**
page picks which one you land on when you open Cube without a deployment specified in the
URL. Leaving it as **Account default** falls back, in order, to the deployment you last
switched to, then the account-wide default an admin can set from the
[deployments list](/admin/deployment#list-of-deployments), then your most recently created
deployment. The control is hidden on accounts with only one reachable deployment.

## Notifications

These switches control email only. Alerts, mentions, replies, shares, access
requests, dashboard reviews and dbt syncs arrive in your [inbox][ref-inbox]
whatever you choose here. In the **Notifications** section of the **Preferences**
page, choose which of them also arrive by email. Only admins see the **Model
syncs** switch, since only admins get these emails:

| Switch | You get an email when | Default |
| --- | --- | --- |
| Alerts | An [alert][ref-alerts] that lists you as a recipient fires or resolves, or usage crosses a [budget][ref-budgets] threshold you get notifications for | On |
| Mentions in comments | Someone [mentions you][ref-mentions] in a dashboard comment | On |
| Replies to comments | Someone replies [in a comment thread][ref-replies] you wrote in | On |
| Model syncs | A [dbt sync][ref-dbt-review] that a webhook started has changes ready to review and the dbt project has no notification list, or a webhook dbt sync starts failing, with or without a list. Admins only | On |
| Shared with you | Someone [shares][ref-sharing] a workbook, a folder, or a chat with you, or approves your access request | On |
| Access requests | Someone [requests access][ref-request-access] to an item you can share, or declines your request | On |
| Dashboard reviews | Someone [requests your review][ref-reviews] of a dashboard, or comments on, approves, requests changes to, or publishes a review you take part in | On |

A switch saves as soon as you change it. Turning a switch off stops the email
only; the notification still arrives in your inbox.

You can also turn a switch off from the email itself. The link at the bottom of
each email, such as **Unsubscribe from Mentions in comments emails**, turns off
that one switch without signing in. Mail apps that support one-click
unsubscribe offer the same action next to the sender. To get the emails again,
turn the switch back on here.

The email is in the language you set under [Language](#language) and links to the
comment, the item, the review or the changes. Cube doesn't email you about a
comment, a shared item or a dashboard you can no longer open, or about a dbt sync
once you're no longer an admin. An email about a declined request doesn't name
the item.

An email address on an alert or a budget that doesn't belong to a Cube user
always gets its email, whatever the Alerts switch says.

End-of-support notices, scheduled tasks and
[report deliveries][ref-report-deliveries] send their own email, as set up on
each of them, and have no switch here.

### Skip email if already read

With **Skip email if already read** on, Cube waits 5 minutes before it sends
a mention, reply, share or access-request email, and sends nothing if you read
or delete the notification in your inbox by then. Marking the notification read
in the inbox counts, whether you select it, choose **Mark read** in its **⋮**
menu or choose **Mark all read**. Opening the comment or the item from
somewhere else does not. Dashboard review and model sync emails don't wait and
go out at once.

The switch is on by default. Turn it off to get each email as soon as the
notification arrives. Unlike the other switches, it can't be turned off from
the unsubscribe link in an email.
